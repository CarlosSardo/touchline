# Blueprint Coverage

This document distinguishes implemented behavior from fidelity gaps. A visible control is not considered complete merely because it exists. Verification entries describe test coverage, not a claim that every check has passed on the current backend.

**Recorded baseline (21 September 2026):** the SQL runtime and real career migration were verified on Azure: all 34 active-world tables and six imported checkpoints passed post-commit checks. Hosted deployment passed private image pull, managed-identity SQL startup, public health and anonymous-rejection checks. The owner confirmed browser sign-in; guest gameplay and full gameplay/browser regression remain separate gates.

**Version-3 verification (22 September 2026):** production build, lint and all 371 backend tests passed against isolated local SQL where required. Four focused full-world browser workflows passed: competition notifications, database filters, academy cohorts and squad controls, including 390px/320px layouts. This is not a fresh pass of the complete 33-scenario browser suite. Expanded-world checkpoint performance and long-running browser career lifecycles remain unverified release limitations. Existing careers require explicit backup-first expansion; application deployment does not upgrade their world or redraw saved calendars.

**Multi-user integration:** account-isolated routing, manual access approval and release guards are source-level behavior. Hosted OpenID Connect sign-in, world creation on approval, deployment and fresh account/release validation require separate confirmation; the historical results above do not certify this change.

**PostgreSQL / Raspberry Pi migration (October 2026):** the runtime moved from Azure Container Apps + Azure SQL to a self-hosted Docker Compose stack with PostgreSQL 18. The Azure-era results above do not certify the PostgreSQL store, the Pi deployment or in-app OpenID Connect sign-in; each needs a fresh recorded run.

**Simulation, market and registration round (21 October 2026):** per-day commits and `players` storage tuning (world migration 2), the FA GBE evidence model (migration 3), signing separated from association/competition registration (migration 4) and club-initiated transfer/loan offers with an offer-frequency setting (migration 5). New and updated SQL-backed tests cover these behaviors (see the entries below). Development measurements: on a 6,400-player world, the `players` table measured 669 MB after 120 simulated days with the old 7-days-per-transaction advance, compared with 32 MB with per-day commits and migration 2. Club offers per open-window week averaged 2.2 (Low), 5.4–5.6 (Medium) and 9.4 (High), about 40% transfers and 60% loans. In those runs every accepted offer completed. GBE (12 nations, about 22,500 senior club players): 8% of players scored zero in a fresh world and 7% after a season, where nearly all did before. A one-season `simulation:check` soak passed its footprint budget (other tables +24.4 MB against a 32 MB budget). The GBE ledger grew 3.7 MB per season on that soak world and was about 27 MB after a season on a 60,000-player world. Not yet recorded: a full `npm run verify` (including the browser suite) of the combined change, multi-season and full-world soaks under the new footprint budgets, migrations 2–5 applied to the live career on the Pi with `db:migrate -- --registered`, and any timing on the Pi itself.

**Living world round (23 October 2026):** a daily world transfer market with AI-to-AI transfers and loans, an FFP gate and sanctions, release clauses and part-exchange deals (migration 6); autonomous club life: affiliate lifecycle, infrastructure projects, directors of football, manager and formation changes, administration, relegation wage-cut clauses and the *World football* feed (migration 7); owners, multi-club groups, takeovers, elections, the 50+1 and UEFA multi-club rules and related-party pricing (migration 8); reorganised player pages with honours, injury history and milestones (migration 9). Development measurements (x86 desktop, not the Pi): three-season soaks of England + Spain and England + Spain + Germany stayed within the footprint budget in every season (first season +60.5/+69.1 MB against 67/77 MB, later seasons +25.5 to +38.4 MB against 38–44 MB; `players` 5.4–6.1 KB per row) with 0–2 FFP breaches per season; market volumes are given under *World transfer market* below. A two-season ownership run recorded 38 takeovers, 13 group acquisitions, 73 elections and 4 blind trusts. Not yet recorded: a full `npm run verify` of the integrated change, a multi-season full-world soak, migrations 6–9 applied to the live careers on the Pi, any Pi timing, and a live pass of the new screens.

## Platform And Persistence

The self-hosted Raspberry Pi + PostgreSQL plan supersedes the retired Azure plan and the former local-only/SQLite requirement. Command availability, setup and deployment are documented in [DEVELOPMENT.md](DEVELOPMENT.md); collaboration and conflict policy are in [CONTRIBUTING.md](CONTRIBUTING.md).

- **Hosting:** one Docker Compose stack on a Raspberry Pi 4 (8 GB, SSD, 64-bit OS): an app container serves React and Express together, one PostgreSQL 18 database holds the account registry and separate per-user worlds/save catalogs, and an optional Caddy container terminates HTTPS. Images are multi-arch (arm64/amd64) GHCR builds from the image workflow, or local builds; deployment is a manual `docker compose` step. PostgreSQL is reachable only on the Compose network and host loopback.
- **Identity and access:** hosted access uses in-app OpenID Connect (Authorization Code with PKCE, `client_secret_basic`) against the configured `OIDC_ISSUER`, on the Pi the self-hosted Authelia, with redirect URI `https://<host>/auth/callback` and scopes `openid profile email groups`. The UserInfo response must belong to the ID token's `sub`. Members of `ADMIN_GROUP` (default `admins`) are admins. `accounts.users` uniquely keys identities by `(issuer, subject)` and assigns a unique `game_schema`; `accounts.access_requests` holds one pending, approved or denied request per identity. The app connects as a non-superuser role that owns the database; operators use the same `.env` settings, and secrets remain in the ignored `.env`.
- **SQL runtime:** asynchronous Store operations use native PostgreSQL SQL over the full schema, with per-world schemas selected through `search_path`. Hosted startup requires the separate account registry; `Accounts.resolve` and `Store.forSchema` scope each request, world and save operation. Local no-auth mode uses an explicitly supplied Store. No startup fallback binds an owner, migrates or seeds. Empty accounts return `hasWorld: false` from `/api/me` and `null` bootstrap; world generation requires explicit `/api/careers/prepare`. `GAME_DB`, `SAVE_DIR` and the Azure SQL settings (`SQL_SERVER`, `SQL_ENCRYPT`, `SQL_TRUST_SERVER_CERTIFICATE`) are obsolete and rejected.
- **Account initialization:** an admin's first sign-in, or an admin's approval of a pending request at `/admin`, creates the player's private, empty world schema and registry row in one transaction; the runtime role is never a PostgreSQL superuser. [scripts/accounts-migrate.ts](scripts/accounts-migrate.ts) is the offline path that creates and validates the registry without copying or seeding. Registered migration modes must cover all worlds. Standalone seeding requires `--seed --apply --yes` and is for a separate new empty development target, never an existing career.
- **Access approval and known gaps:** the first sign-in of a non-admin records a pending access request and shows a waiting screen. Admins approve or deny it at `/admin` (same-origin POSTs); approval enforces `MAX_PLAYERS` (approved non-admin players; `0` allows admins only) and `DB_SIZE_LIMIT_GB`, and a denied request can be approved later. There are no emails or notifications: admins check `/admin`. Approved access cannot be revoked in the app (disable the user at the provider instead), and there is no self-service account deletion; deletion and data removal remain operator actions.
- **Portable saves:** `.touchline.gz` contains a compressed logical world checkpoint, not a SQLite database or a complete save-catalog export. SQL catalog entries and 1 MiB compressed chunks persist separately from active-world tables. IO uses bounded streaming and temporary staging, validates before replacement, and restores active tables transactionally. The 16 GiB compressed / 64 GiB expanded safeguards are format limits, not cloud capacity guarantees. Autosave retention is per career; imported legacy checkpoints are not automatically pruned. Checkpoints written before the GBE and registration tables (`ADDED_WORLD_TABLES` in [server/sql-schema.ts](server/sql-schema.ts)) may omit them: those tables restore empty, the GBE baseline is rebuilt once, existing players keep their registrations, and a missing offer-frequency setting reads as Medium. Checkpoints written before migrations 6–9 may also omit `sanctions`, `club_projects`, `owners`, `club_ownership`, `ownership_events`, `player_honours`, `player_injuries` and `player_milestones`: they restore empty (no sanctions or projects until the game decides some), owners are regenerated from the world seed exactly as at generation, missing Spanish release clauses and relegation clauses are added, and honours, milestones and currently running injuries are backfilled once on the next advance or save load (earlier injuries are not reconstructed).
- **Legacy preservation:** the one-time SQLite import tool (`data-migrate.ts`) is retired with the Azure SQL runtime; SQLite-era careers reach PostgreSQL only as `.touchline.gz` exports made with an earlier release. Retain all SQLite originals and companions offline permanently, never delete them after conversion.
- **Test isolation:** local integration/browser checks exercise the full SQL schema, not SQLite or a partial substitute. The harness selects fresh `touchline_test_` / `touchline_e2e_` schemas; account tests belong to the persistence verification group. Remote execution requires `SQL_ALLOW_REMOTE_TESTS=true` and matching `SQL_TEST_DATABASE`/`SQL_DATABASE`. Browser tests confirm test mode, database and exact schema before mutation. Local supplied-store/synthetic-auth coverage is not hosted sign-in acceptance. `npm run test:local` uses a disposable PostgreSQL 18 container or, with `--no-docker`, an existing loopback PostgreSQL. Missing SQL must fail setup, not skip coverage or fall back to a player's world.
- **Storage budget:** historical SQLite measurements for older world versions were about 600 MiB unexpanded and 3 GiB expanded. These are not version-3 measurements or PostgreSQL size estimates. The Pi's SSD must accommodate active data, indexes, compressed snapshots, WAL, local `pg_dump` backups, test/restore headroom and growth; `DB_SIZE_LIMIT_GB` guards approvals. Actual PostgreSQL usage and migration/restore performance on the Pi remain to be measured. The `simulation:check` season soak fails, rather than warns, when the `players` table exceeds 10 KB per row or the other world tables grow in a season beyond `seasonBudgetMB` (the full world's 300 MB season budget scaled by fixtures played, at least 32 MB).
- **Cost and availability:** one always-on Pi; availability depends on its power, network and SSD. There is no automatic failover. Daily `scripts/pi-backup.sh` dumps (with retention) and copies kept off the Pi are the recovery path. Do not add paid services or extra always-on containers.
- **Release compatibility:** startup never migrates or seeds. Upgrades back up first, then apply `db:migrate -- --registered` to every registered world before starting the new image. Careers move between installations, including from the retired Azure deployment, only as `.touchline.gz` exports imported in-app, or as whole-database `pg_dump` restores.
- **Rollback safety:** roll back by restoring the pre-upgrade `pg_dump` with `scripts/pi-restore.sh` together with the matching image digest, never by running an older image against migrated data, dropping the registry, weakening sign-in or reseeding.
- **Deployment acceptance:** the Pi deployment needs fresh operator confirmation of sign-in, human profile display, admin first sign-in, pending request and approval at `/admin`, private-world creation, account-scoped saves/actions, pending/denied rejection, backup/restore and imported Azure-era careers. Applying migrations 2–9 to the existing Pi careers and a live pass of the integrated flow (sign a player without a GBE, see him unregistered, receive and accept a loan offer at the chosen frequency, track the loan to its return and see his registration re-evaluated) also need recording, as does a live pass of the living-world screens (World football feed, club Ownership tab, owners browser, Financial regulations sanctions, boardroom projects, release-clause and part-exchange negotiation, reorganised player sheet) on a migrated career. Do not report these gates as passed without an actual run.

## Career And Navigation Workflows

- **Human profile:** `/api/me` exposes the resolved account ID, the provider's username, display name and email, and the admin flag, not the in-game sporting director. Profile refresh does not change the issuer/subject identity, schema ownership or the fictional director's name/background; world checkpoints do not contain the account registry.
- **Career start:** Continue, New and Load screens operate within the resolved account. New empty accounts do not create a world on login/bootstrap; explicit preparation precedes director/background/club selection. Named careers, SQL metadata, preservation before switching and autosave retention stay per account/career. Existing lifecycle tests do not by themselves certify hosted cross-user isolation.
- **Save organization:** career folders in both load menus group only the resolved account's SQL catalog entries by persistent ID, with separate manual/autosave sublists and individual snapshots. Grouping does not merge/delete checkpoints or expose another user's catalog. Tests cover duplicate names, unknown legacy identity, retention, cancellation and deletion protection.
- **World browser:** server-side search, country/confederation/type/tier/reputation filters and pagination over every stored team. Club, B-team and national-team dossiers expose squads, competitions, staff, fixtures and history. An API test visits every page and checks complete ID coverage.
- **Shared screen structure:** the sidebar groups related screens; shared page/section headings and consistent stat bands organize actions and summaries. Squad and academy statistics reflect the selected team or cohort. This source-level description does not certify current desktop/mobile browser acceptance.
- **Player database filters:** every numeric criterion is a min–max pair (`${name}Min`/`${name}Max` on `GET /api/players`, shared domains in [shared/player-search.ts](shared/player-search.ts)): age, current ability, potential, value, weekly wage, months left on the contract, division tier, height, weight, the level of a chosen attribute or personality trait, match rating, appearances, minutes, goals and assists. Categories stay single selects: nationality, position, age group, preferred foot, fitness, contract status, availability, club country, league and club (the club list follows the league; changing a parent clears its dependants). Core groups are *Player*, *Ability & fitness* and *Contract & money*; advanced groups are *Club & competition*, *Physical & attributes*, *Personality & traits* and *Season performance*. Typed bounds apply after a short pause; a reversed pair is searched in order and an out-of-range value clamped, with an inline note, and amounts accept shorthand such as 750k or 2.5m. One chip per criterion ("Age 18–21", "Value £1M–£5M", "Contract left ≤ 6 months") shows the applied search, search text and shortlist state even when advanced controls are collapsed, with individual removal and a full reset. Server-side sorting/pagination returns to the first page when criteria change; club, league and division filters are a semi-join on `clubs` that keeps the player indexes usable. Height and weight are indexed `players` columns (migration 11) copied from the profile at creation, growth and save restore. Skill, lifestyle, trait and contract-status filters read the profile JSON, so they are checked on at most the first 10,000 players (in the requested order) that pass the other filters: pages are exact, a larger total shows as "N+".
- **Squad browsing:** independent first/reserve team and Senior/U19/U17 selectors, text/position/readiness filters and positional coverage counts. Readiness distinguishes injured players, fitness below 60 and fit players at 60 or above. Ability, potential, fitness, age or name ordering is retained within goalkeeper/defender/midfielder/forward sections.
- **Academy review:** U19/U17/all-youth cohorts scope prospects, priorities, mentorship and youth competitions. Search, position, sort and review focus expose next-season age-out cases, injury/fitness/burnout concerns and unpaired players. These are review aids, not automatic promotion or mentoring decisions.
- **Expanded careers:** world version 4 (`WORLD_VERSION` in [shared/world-rules.ts](shared/world-rules.ts)) builds 211 associations from the world catalog; 107 have their own league pyramid of one to six tiers (England 6, Spain 4, Germany/France/Italy/Portugal 3, Netherlands and Luxembourg 2) and the rest use home-based player pools or play in a host pyramid. New clubs are generated towards squad targets of 25 senior, 20 U19 and 20 U17 players (20 for B teams; `SQUAD_MINIMUMS`, a generation target rather than a registration rule). Replenishment ignores retired players and expired contracts when counting positional coverage. Fresh version-4 SQL totals remain unverified.
- **Explicit world upgrade:** existing careers, including version 2, require **World > Expand career world**. The guard uses `WORLD_VERSION`; a current-version career is unchanged. A named **Before world expansion** checkpoint commits independently before transactional expansion and remains available after rollback. New memberships and structural changes activate next season once a calendar exists; only 1 July without fixtures permits immediate activation. Current-season memberships and fixtures are preserved. Deployment does not automatically expand a career or redraw its calendar.
- **Legacy preservation during expansion:** existing IDs, cities, players/profiles, contracts, cash, wages, budgets, dates and history remain intact. The name helper only localizes incompatible generated city-plus-English-suffix club names; valid local/custom names remain. Recognized generated B-team names follow renamed parents. Missing clubs and roster places are added without reseeding or retroactively rewriting player identities.
- **Identity and squad assignment:** culturally grounded names, birthplace, family heritage, biographies and one to three recorded nationalities are distinct from international representation and employer location. Nationality filters include secondary nationalities. Eligible players can move reversibly among owned first/reserve/U19/U17 squads without ownership or wage changes; active loans and birth-date cutoffs constrain destinations.
- **Fictional identity generation:** new-world players and intakes use the catalog's fictional diaspora and heritage links (up to three family roots) and curated local name pools. These are not census or multiple-passport rates. Heritage percentages are narrative family branches, not racial or genetic inference, and do not affect ability, personality, traits or value. Existing player profiles are not rewritten; `createIdentity` in [server/people.ts](server/people.ts) applies these rules.
- **Competition subscriptions:** persisted favorites select fixture, result, draw, standings and winner updates from actual career data. Global topic/priority preferences feed the inbox, office and unread count consistently; muted items remain in the archive. Grouped filters and pagination cover competition browsing and correspondence. API/browser tests cover persistence, duplicate suppression, archive access and readable mobile controls.
- **Profile links:** player and team names link across world tables, squads, standings, fixtures, scouting, transfers, loans, partnerships and analytics. A browser test follows team to squad player and back to the team.
- **Transfer stages:** explicit enquiry, club talks, agent talks, contract review/revision, conditional signing, medical, final paperwork ("Registration" stage) and completion. Completion checks only the transfer rules in `canSign` ([server/eligibility.ts](server/eligibility.ts)); association and competition registration are decided after the signing and never undo it. Accepted incoming offers delegate personal terms to the buyer. Regression tests reject illegal transitions and verify no early payment or ownership change.
- **Offer creation:** separate reloadable Club offer and Player contract routes isolate fee/loan/clause editing from wages/bonuses/role/promises. Club acceptance links to personal talks; agreed terms and history are collapsed summaries. Cancelling initial selection has no negotiation side effects. Tests cover routing, resume, unchanged salary during club talks, instalment presets and loan guarantees.
- **Buying options:** permanent bids can include seller loan-backs until the season end, one year or two seasons. Loan-backs use a separate "Loan-back" spell after registration, with the buyer owning the player and the seller paying 100% of wages; two-season and minor loan-backs are domestic-only where FIFA international loan limits apply. Pre-contract agreements model FIFA RSTP art. 18.3/Bosman moves for players in the final six months of a contract, with UK same-association domestic approaches deliberately blocked until expiry. They skip club fee talks, reserve signing costs and schedule a free transfer after the old contract expires and a window is open.
- **Future arrivals:** guardian-consented agreements for ages 14-17 enter a Scheduled stage instead of registering early. Arrival is based on birth date and the next open window. Budget is reserved on signing and carried over seasons; cash and wages change only on registration unless the user places the minor at a same-association affiliate. Affiliate placement settles the full selling-club fee immediately, even if the original bid used instalments, registers the player domestically with the partner club, preserves only the onward agreement, and pushes arrival when needed to satisfy the 16-week FIFA bridge-transfer presumption. Medical/eligibility failures or cancellation refund only any remaining reservation; original-contract expiry waives the former club's transfer fee. Tests cover early-move prevention, normal enquiry deadline expiry, exact arrival, next-window timing, budgets, refunds and browser persistence. This is a conditional game mechanism, not a complete model of domestic law governing minors' employment.
- **Youth eligibility:** recorded contract status distinguishes amateur registration from protected/future professional agreements. No-fee youth approaches disclose modeled training compensation. EU/EEA 16-17, same-country/inter-association and evidenced non-football parental relocation routes require prior approval for international registration. Unsupported circumstances remain blocked. Legacy contracts are not inferred to be amateur. Sources, deliberate legal simplifications and compensation caveats are in the [registration and eligibility guide](website/src/content/docs/play/registration.md) and the [README credits](README.md#credits-and-data-sources).
- **Player interest:** deterministic factors explain ambition, opportunity, development, continental football, adaptation, loyalty, wages, security, promise credibility and negotiation trust. Personal terms are previewed without side effects; wage attraction is bounded, and an unsuitable move can still be refused. Tests verify credible roles, unbacked promises, high-wage refusal and read-only previews.
- **Appearance:** a dedicated section offers Minimal/Classic layout themes alongside Light/Dark/System and custom HEX accents. Smaller headings, flat save folders, collapsed histories and separate contract steps reduce visible clutter. Theme preferences persist through reload and career creation.
- **Market cadence:** the world market ([server/world-market.ts](server/world-market.ts)) replaces the former daily attempt loop with one set-based pass per market day over the daily club policy snapshot ([server/club-policy.ts](server/club-policy.ts)): demand (needs by position and age, director-of-football policy, owner ambition) is matched with supply (surplus, unhappy and expiring players, development loans), weighted by a season calendar with a deadline-day surge. Squad size, goalkeeper cover, wage room, cash, FFP headroom, embargoes, expected registration (an AI club only pursues players it expects to register: a recruitment preference, not a signing rule), pending talks and the sellers' squad minimums constrain AI-to-AI deals. All user-club sales still require acceptance, except a paid release clause. These are game balancing rules, not a statistical reproduction of a real transfer window.
- **Club offers for the director's players:** [server/market-offers.ts](server/market-offers.ts) takes a daily snapshot of every other club's needs (first-team depth by position), level, budget and wage room net of money and wages committed to open deals. It skips injured, loaned-out and already-negotiating players and pre-validates personal terms, affordability and the transfer rules before an offer is sent. **Transfer/Loan Offer Frequency** (Settings › Simulation; Low/Medium/High, default Medium, persisted with the career; older saves read as Medium) sets weekly targets of about 2/5/9 relevant offers per open-window week, daily maxima, per-player and per-club open-offer limits, and occasional above-value bids (115–130% of value) for unlisted key players on Medium/High. These are targets, not a fixed number: supply of suitable player/club pairs caps every level. The same club does not return for the same player within 42 days. Accepting one offer withdraws the others, and clubs withdraw when the player is injured, the budget no longer covers the deal or they sign someone else for the position. Offers stop seven days before deadline day. In the ten days before a window, clubs make pre-agreements that start on the opening day. Between windows only domestic emergency loans (borrower with three or more unavailable seniors) are possible. Tests cover frequency parsing and persistence, the window calendar, relevance and availability filters, affordability, volume scaling, withdrawal and an accepted loan tracked to its return. Development runs measured the volumes and completion rate given in the status note above.
- **Signing versus registration:** [server/eligibility.ts](server/eligibility.ts) (with the pure labels in [shared/eligibility.ts](shared/eligibility.ts)) is the single source of truth for four layers: contract, association registration (`player_registrations`, per player and club: registered/pending/not_registered/refused/not_required, with reasons and next review), competition registration (`competition_registrations`, per player, competition and season) and match eligibility per fixture. `canSign` blocks only on the window, budgets/embargo, FIFA Art. 19, loan rules and contract validity, never on GBE or quotas. Work authorisation is modelled only for English registration: British/Irish nationals and players moving between English clubs with an existing registration need no GBE, others need a passing GBE (insufficient points = refused, no evidence = pending, reviewed after 28 days). An approved registration lasts for the club spell. Foreign quotas apply to domestic senior league/cup registration, not to signing; continental competitions need only the association registration. Existing players in migrated worlds keep their registration (no stored row) and quota lists are rebuilt lazily. Re-evaluation runs after GBE refreshes, when a window opens, every 28 days for open cases, when a quota place frees, at season rollover and on loan start/return/recall. Tests cover the label combinations, a signed-but-unregistered completion, loan-out/return re-evaluation, GBE-free loan-ins and free agents, quotas moving to registration, GBE-refresh reviews, older checkpoints without the tables and a live-world v4 migration.
- **Match eligibility and statuses:** both match-selection paths exclude players who are unregistered for the competition, injured or suspended from competitive fixtures; friendlies and training need only a contract. Squad lists, the database, Boardroom › Squad registration and the player sheet show *Signed · eligible*, *Signed · not registered*, *Registration pending*, *Ineligible · insufficient GBE (x/15)*, *Eligible after requirements (date)* and *On loan · eligible*. The player sheet separates contract, association registration, competition registrations and next-match eligibility with reasons and the GBE breakdown, and previews *Registration if signed* for other clubs' players.
- **Day-by-day advance:** `/api/advance` commits each simulated day and its autosave separately. A failure on a later day returns HTTP 200 with the days kept and an `error` message; a failure on the first day is still a 500. Unexpected errors are logged with operation, route, SQL error code and stack. Weekly finances are one set-based statement, cup-round fixtures are created in lazy batches, club friendlies avoid per-match squad queries, and `Store.vacuum` reclaims `players` row versions weekly, after heavy match days and at rollover. An API test injects a mid-request failure and checks that earlier days are kept and logged.
- **Journalists and discussion:** five fictional sources have distinct beats, styles and reliability profiles. Actual bids/agreements/registrations generate labelled reports and persistent comments; player features, match analysis, club roundups and press responses use saved career facts. The UI filters club/world coverage by topic, player text and journalist, exposes source profiles and allows reading full discussions. Tests verify source identity, report versus confirmation status, persistence, idempotence, search and responsive browser interaction. Narratives remain rule-based, not a generative-AI or real-news service.
- **Contract economics:** permanent-transfer instalments have exact dated cash schedules, full budget reservation and no double-counted sale profit. New and existing sell-on clauses split receipts as cash arrives. Buy-back rights belong to the selling club, expire, become void on subsequent ownership changes and open personal talks at the binding fee. Loan-backs reduce the selling club's floor by 3%/5%/7% for season/year/two-season stays (up to 10% for important players) while reducing buyer ceilings by the same base rates. Incoming offers accept counterproposals with these club terms. Payment/rights tables and player dossiers expose the agreements; tests cover timing, ownership, invalid terms and duplicate processing.
- **Currency and numbers:** a persisted currency selector converts displays and monetary inputs at fixed game rates while leaving stored GBP amounts intact. Compact `K`/`M`/`B` labels shorten large values; exact inputs remain editable. A custom HEX accent editor validates and normalizes colour codes. Browser checks cover settings persistence, input conversion, save-finance preservation and mobile layouts.
- **Director assistant:** each club starts with one assistant and persisted, configurable duties. Weekly briefings are enabled by default; shortlist, scouting, renewal drafts, individual training and loan monitoring are opt-in. A rolling allowance caps scouting costs, private contracts cannot be signed automatically, reports link to players/drafts, and vacant roles pause work. Unit/API/browser checks cover delegation, ownership, replacement, spending and persistence.
- **Unexpected events:** six seeded event families offer bounded financial, fitness, morale, supporter or trust effects. Low/Medium/High sets daily probabilities of 2.5%/7%/15% with minimum gaps of 10/6/3 days; pending events block new ones. Choices have a three-day deadline and a no-cost default. Responses are idempotent, club-scoped and checked for affordability; tests cover frequencies, expiry and office/Boardroom workflows. These frequencies are game-balance choices, not real-world incident statistics.
- **Affiliates:** every non-national club has a starter connection visible reciprocally. New proposals choose an affiliation type and require independent counterparty willingness as well as funding. Reputation balance, purpose-specific benefits, direct competition and network capacity determine the other club's decision. Preview reasons are visible in Boardroom and direct partnership dialogs; refusal never spends funds. Approved payments are credited to the partner. Three-day board reviews and 28-day request cooldown remain. Transfer desk actions can use sufficiently strong senior-club partners for domestic minor placements or on-arrival development loans, with ineligible clubs shown alongside rule reasons. Tests cover type-dependent acceptance/refusal, cash conservation, browser choices and non-destructive upgrades.
- **Universal appearance history:** every actual participant, including substitutes and players outside the managed club, gets an indexed SQL appearance record. Seasons, team/competition summaries and paginated match lists survive rollover. Older versioned snapshots backfill without modifying match data or duplicating rows.
- **Individual reports:** match links focus the selected player and expose minutes, starts/substitutions, rating, goals, assists, xG/xA, passing, creation, duels, defending, discipline, goalkeeping and individual maps. Backend assertions compare stored appearance values to match statistics; browser coverage follows a non-managed player into their report on desktop/mobile.
- **Youth internationals:** five national teams per association (Senior, U21, U20, U19, U17). UEFA U21/U19/U17 qualifying is simulated; other confederations and the FIFA U-17/U-20 World Cups take entrants by strength. Squads are named before fixtures; FIFA-window and close-season duty is always released, otherwise clubs decide and the user's club follows the **Release for youth tournaments** setting. The Internationals page lists this season's tournaments, the club's players away or kept back and each national team's squad, eligibility cutoff and fixtures; player dossiers show caps per team. Two finals were moved to fit the 1 July rollover (U21 EURO 12–27 June, U19 EURO from 2 July). SQL tests for this system have not run yet.
- **Call-ups:** temporary moves inside the club family (U17 → U19 → B team → first team and back) for the next match, a number of days or until a date (at most 120 days), ending at rollover. The coach calls up automatically or proposes when **Coach call-ups** is off; a per-club debut budget limits first-team debuts, and the director can make up to three development requests, with the coach's latest reason shown. Rates are tunable heuristics, not real-world statistics.
- **Transfer battles and club transfers:** rival clubs can bid for the same player, leading to a best-and-final round and possible hijack. Player dossiers list moves and season statistics (goals and assists of every competitive match; ratings where match records are kept); club profiles list arrivals and departures per season with fees and agreed clauses. Club in/out counts include loan returns but no longer moves between the club's own teams or call-ups, which are listed in a separate collapsible *Squad movements* block.
- **World transfer market:** AI clubs make transfers, loans (standard, with option, and development loans where the parent covers more of the wage when the borrower cannot), free-agent signings between windows (two market days a week for clubs short in a position) and part-exchange deals among themselves. Clubs may sign first and sell later within the window (sell-to-buy); wage room counts wages leaving before the window closes. On deadline day, clubs still over budget end surplus contracts by mutual consent with a severance payment and loan players out to cut wages. Boards review AI wage budgets weekly as soft targets bounded by FFP headroom, cash and owner ambition; wage budgets are capped at a sustainable level at the season reset, and AI renewals at rollover are budget-aware (`aiRenewalTerms` in [server/youth.ts](server/youth.ts); some players refuse and become free agents). The director's own renewals are unchanged. Lower-tier finances were corrected: split leagues are no longer counted twice (England's sixth tier, Spain's third and fourth), lower divisions receive central distributions and solidarity, and running costs follow actual crowds. `simulation:check` reports moves per club per season by tier against calibration bands (`MARKET_TARGETS`: tier 1 8–15, tier 2 6–12, tier 3 4–10, tier 4+ 2–10, lowest tier 2–6), the loan, free-agent, deadline-day and between-window shares, part-exchanges, release clauses, FFP breaches and sanctions; the bands are reported, not enforced. Development three-season soaks (England + Spain, England + Spain + Germany) measured tier 1 6.6–8.7, tier 2 5.9–7.6, tier 3 5.6–6.3, tier 4+ 4.0–4.6 and lowest tier 3.1–4.4 moves per club per season; loans 25–41%, free signings 2% in the first season and 12–13% after, deadline day 3–6%. Tests cover needs, AI transfers and loans within budgets, wage room and FFP headroom, embargoes, window wage room, deadline-day releases, the end of world loans, release clauses and part-exchanges.
- **FFP gate and sanctions:** with FFP enforcement on, every AI purchase or loan-in is checked against the buyer's projected squad-cost headroom (world market, approaches for the director's players, rival bids and completion). [server/sanctions.ts](server/sanctions.ts) (`sanctions` table, migration 6) reviews each season after the accounts close: UEFA squad-cost breaches are settled (a fine now and the same amount conditional on next season's compliance), with a one-season registration embargo when more than 10 points over or repeated; Premier League breaches of the 85% ratio pay a levy, and from 15 points over (or repeated) lose 6 points (10 from 30 over, +4 when repeated); losses beyond UEFA's acceptable deviation are settled, with an embargo when more than twice the deviation or repeated; a missed settlement target is charged and becomes an embargo. Weekly, a club more than four weeks of its wage budget below zero cannot register new signings until its balance is positive. Points deductions go to `standings.deducted` (the media and call-up paths no longer count them twice). The director's club shows squad-cost headroom and sanctions under *Finances › Financial regulations*.
- **Release clauses and part-exchange:** [shared/release-clauses.ts](shared/release-clauses.ts) and [server/deal-clauses.ts](server/deal-clauses.ts). Every professional contract at a Spanish club carries a clause (5–8× value for prospects, 2.5–4.5× for established players, 1.5–2.5× for veterans); about 12% of contracts elsewhere carry a negotiated one (1.5–3×). Existing worlds receive missing Spanish clauses on the next market day and every four weeks after. A buyer paying the clause cannot be refused; personal terms still apply. The director can pay one in club talks (**Pay release clause**) and set one in personal terms; AI clubs pay clauses, including for the director's players (at most one such approach every 60 days). **Include a player (part-exchange)** adds an adult first-team player to a permanent bid at a valuation from his value, the seller's need and fit; the deal fails if he is no longer available at completion. AI clubs also make part-exchanges.
- **Club life:** [server/club-life.ts](server/club-life.ts) runs the daily and weekly club passes (endpoints `/api/club-life`, `/api/clubs/:id/life`; rules `AFFILIATE_LIFE`, `PROJECT_RULES`, `DIRECTOR_RULES`, `MANAGER_RULES`, `ADMINISTRATION_RULES`, `RELEGATION_CLAUSE`). AI clubs below their partner target (1–3 by reputation) seek affiliates under the existing consent and fee rules (domestic, or heritage-linked abroad for strong top-flight clubs); yearly reviews adjust strength from loan outcomes and end weak, idle, same-division, unaffordable or outgrown agreements; in windows, clubs lend young surplus players (17–21) to affiliates (cross-border only for adults, never into the UK associations). Infrastructure projects (`club_projects`, migration 7) upgrade facilities or the academy against same-country, same-tier peers, expand stadiums near capacity or build new ones (26 weeks' planning, two to three years' building, 70% borrowed); weekly payments are excluded investment for FFP, and completion raises facilities, academy or capacity. The director's board decides its own projects (boardroom and club page). AI clubs in tiers 1–3 or with reputation 50+ employ a director of football whose policy (balanced, youth first, value, stars) follows his style, owner ambition, finances, philosophy and a member club president's promise, held at least 91 days. Weekly sacking chances rise with crisis and lost trust (70-day grace); new managers bring a formation and style weighted by country and tier. In a development run of England + Spain from 1 July 2026 to late August 2027, 66 affiliate agreements were formed, 42 ended and 235 development loans placed, and there were 121 manager changes with 90 formation changes. Tests cover affiliates, projects, directors, manager changes, owner rescues, administration, relegation clauses and restoring saves made before club projects.
- **Administration:** a club whose cash, less transfer instalments due within 91 days, stays below −40% of a season's revenue (at least £250k) for ten weekly checks enters administration unless a wealthy, patient owner bails it out (once a year at most). It loses points (England 12, 10 below tier 4; Scotland 15; Germany 9; Spain 0; others 10; deferred to next season when its league is over), is embargoed, has its top earners listed for sale (up to five, a quarter of the senior wage bill, keeping 18 seniors), halts projects and is put up for sale. It exits when its cash position recovers after 12 weeks, or through a creditors' write-off at 26 weeks. For the director's club, an office notice and the boardroom list the board-imposed sales and those players cannot be taken off the list.
- **Relegation wage-cut clauses:** 25–50% cuts, stamped at world generation and on signing (older worlds backfilled once): about 80% of contracts in tiers 2–4, 45% at amateur level, and in the top flight none at established clubs (reputation 72+) rising as reputation falls. Applied at the rollover on relegation with a morale drop and news; shown on the contract.
- **World football feed:** [server/world-news.ts](server/world-news.ts) publishes AI activity as `Worldwide` news (kept out of the director's inbox) with kinds for transfers, loans, contracts, affiliates, infrastructure, directors, managers, ownership, sanctions and administration; `GET /api/world-news` filters by kind, association, club and text, and *Media › World football* shows it.
- **Ownership:** [server/ownership.ts](server/ownership.ts) (`owners`, `club_ownership`, `ownership_events`, migration 8) gives every club an owner from the world seed, identical for new worlds and backfilled older saves. Owner types are local, billionaire, state, private equity and members; a stake of 40% or more controls. Member-owned: Germany (50+1; up to two works teams exempt), Sweden, Norway, Argentina, Spain's top two and Portugal's top three, among others; English and Italian clubs are almost all privately owned. Eight fictional multi-club groups. State owners and ambitious billionaires add equity each season (FFP equity, not revenue); private equity charges interest and fees on loaded debt; asset strippers take dividends and cut budgets; a wealthy, ambitious owner may add equity once a season when the director asks the board for funds. Takeovers run rumour → bid → completion over weeks, and some collapse; groups expand abroad, supporters' trusts can take over struggling lower-tier clubs, and at 50+1 clubs outsiders only buy a minority. Member clubs elect presidents every 2–4 years (4 in Spain, Portugal and Germany; 3 in Brazil and Turkey; 2 in Sweden and Norway), with early elections when results and mood collapse. UEFA's multi-club rule: a club placed in a blind trust before 1 March may play in the same competition as its sister club (no dealings between them); otherwise the lower-placed club is excluded and replaced by the next eligible club. Related-party deals count at fair value in FFP (the agreed fee if within 15% of market value, else market value); sister clubs are preferred market partners. If the director's club is taken over, Board news and an office notice follow each stage; the new owners set a target finish and budget and review the director after 120 days against a board-confidence target of 35–60 (by their ambition), ending the career at the club if it is missed; a new president at a member club starts the same review. UI: the club page's *Ownership* tab and the owners/groups list in *World*; endpoints `/api/clubs/:id/ownership`, `/api/ownership`, `/api/ownership/notice`. A two-season development run recorded 38 takeovers, 13 group acquisitions, 73 elections and 4 blind trusts, about 4.4% of clubs changing hands per year (about 8% in top flights). Tests cover generation and backfill, takeovers, elections, the UEFA rule, related-party pricing, the director's review and saves made before ownership.
- **Player pages:** the history API returns transfers (moves between different clubs, including loans and their ends) separately from squad movements (B-team/U19/U17 moves and call-ups; a call-up and its return fold into one entry with its length), and club *Transfers* tabs no longer list squad moves. Season statistics are grouped season → club → competition with subtotals, a career total and club/competition filters; friendlies are listed separately and never counted. The player sheet's tabs are Overview, Career, Attributes & development, Scouting, Contract & registration and Medical, without duplicated sections (the projection appears once; release and relegation clauses under the contract; wellbeing under Medical; caps under Career).
- **Honours, injury history and milestones:** `player_honours`, `player_injuries` and `player_milestones` (migration 9, [server/player-records.ts](server/player-records.ts)). Honours cover league, cup, continental and international (senior and youth) titles for players who appeared for the winner, with a regular/squad/limited role; league titles are recorded at rollover, cups and tournaments on the day decided. Injuries are recorded from full matches, fast matches and weekly training with diagnosis, severity, expected return and rehab updates (`GET /api/players/:id/medical`). Milestones cover senior, club and international debuts, first goals and appearance/goal/cap thresholds; whole-career milestones only for players under 20 at world start without pre-game minutes. Older worlds and saves are backfilled once (honours from recorded champions, milestones from finished seasons' statistics and this season's appearances, currently running injuries). Development measurement: about 0.6% more time per simulated day on the full world.

## Standings System

Tables store played, W/D/L, GF/GA/GD, points, last five, home/away W-D-L, xG, xGA and Poisson xPts. Results update both sides consistently. Points deductions (FFP sanctions, administration) are stored in `standings.deducted` and subtracted once from the points. The UI distinguishes title/qualification, middle and relegation zones. Every competition page (leagues, split leagues, cups, super cups, continental, international and youth competitions) also ranks its scorers from `player_season_stats`: goals, then fewer minutes, more assists and name, with players level on goals sharing a rank and a player's clubs in the same competition season added up.

League outcomes influence morale, manager trust, board confidence/pressure, fan mood, media stories, reputation, valuation and transfer interest. Winning/losing streaks and result margins feed momentum, hype and crisis. Threshold events include meetings, protests, tactical changes, manager dismissals, unsettled-player requests, emergency-loan availability and AI youth promotions. Match outcomes consume momentum, confidence, pressure and tactical context. Qualification draws use prior standings when available. Previous season tables are archived before rollover.

## Rules And Verification Improvements

- **UEFA draws and qualification:** 36-club Champions/Europa league phases have eight unique opponents, two from each of four pots, with one home and one away per pot. Conference has six opponents, one from each pot and three home/three away. Both protect against same-association fixtures and more than two opponents from another association. Small exact solver models construct the draw and matchdays. Domestic finishes, domestic cups, continental titleholders and rolling simulated association coefficients inform entry.
- **Qualifying completeness:** all modeled eligible UEFA entrants enter a direct or qualifying field, with byes and enough rounds to reach the main-phase quota. Luxembourg is explicitly covered by regression tests, as are duplicate competition entry and late qualifying dates. Existing saved fixtures are retained; the corrected path applies to newly generated seasons.
- **Country audit:** the 243-entry association catalog has 16 documented reserve policies, 20 historical examples and 207 unverified entries. Documented sources comprise two `official-rule` entries (Germany, Netherlands), three `official-participation` examples (England, US, Canada) and 11 secondary references. Historical evidence is secondary and does not authorize present-day entry; unknown permissions remain conservative. Participation is not a complete rulebook, and no label certifies federation-wide regulatory accuracy. Italy/Belgium reserve access, Germany/Netherlands/Portugal ceilings, parent-club separation and separate US/Canadian development pathways are modeled. Regional branches, licensing, registration and cross-border exceptions remain simplified; football confederation is separate from geography.
- **Knockout ties:** senior UEFA rounds before the final use two legs, persistent tie metadata and aggregate progression. Away goals are disabled. Finals are single and neutral; applicable tied senior games use extra time and shootouts. One team advances per tie, not per leg.
- **Match laws:** the version-3 engine models five substitutions within three regulation windows, a half-time exception, an extra-time change, injury exits, yellow/red cards, second cautions, minimum-player abandonment, variable stoppage time and two extra-time periods. Shootouts use eligible on-field takers and separate scores. Competition-scoped suspension records affect subsequent selection.
- **Player valuation:** nonlinear quality anchors, bounded youth-potential premiums, age/position resale curves, league strength and a remaining-contract taper replace a single broad price curve. Contract value reaches zero at expiry; inflation, form, hype, injury and club/standings modifiers are bounded. Prices remain game estimates, not licensed market data or promised transfer receipts.
- **Club valuation and revenue:** query models feed Finances and club profiles with a revenue-multiple enterprise estimate, separate from squad market value and cash balance. `projectedOperatingRevenue` and `weeklyFinances` use the same league-aware `estimateClubRevenue` calculation for commercial and matchday income. Forecasts use expected home matches; weekly cash flows use senior home games actually played. Estimated enterprise value is not transfer-budget availability or an audited sale price.
- **Starting finances:** `initialClubFinances` calibrates cash, transfer allocation and wage budget only for newly generated expanded-world clubs, including additions during explicit expansion. It does not reset existing clubs' cash, wages, contracts or budgets. Future operating receipts follow the shared revenue model; historical accounts are not reconstructed.
- **Financial periods:** operating revenue, wages, other costs, excluded investment, equity, agent costs and disposal profit are recorded separately. Player acquisition costs are amortized over the contract up to five years; sales use remaining book value. Source-labelled monitoring models UEFA's 70% squad-cost limit and equity-supported acceptable deviation, or the English top-flight 85% SCR where applicable. Projections and closed accounts are distinct. There is no generic fixed GBP 100m automatic registration embargo.
- **English registration:** published FA 2026/27 points tables for international appearances, domestic/continental minutes, team results/progression and league quality replace the ability shortcut. British/Irish nationality and an existing English registration are considered. The GBE decides association registration after the signing, never the signing itself: insufficient points leave a signed player unregistered (friendlies and training only) until a review grants it, and missing evidence leaves the case pending rather than scoring zero. The player sheet exposes the per-criterion breakdown, evidence and reasons.
- **GBE model:** the pure calculator in [shared/gbe/](shared/gbe/) applies ruleset `fa-2026-27`: pass mark 15, Exceptions Panel band 10–14 (outcome `panel`, not granted automatically), automatic pass from the international table, British/Irish exempt. Six criteria are scored: international appearances, domestic minutes, continental minutes, league position, continental progression and league standard. Windows: club minutes over the last 12 months, senior internationals and Elite Significant Contribution over the last 24 months (12 for youth). Each criterion is `scored`, `zero` (data exists, no points), `no_data` (missing data is not a zero) or `estimate` (pre-game career estimate). Outcomes are `auto_pass`, `pass`, `panel`, `fail`, `exempt` and `no_data`. [server/gbe.ts](server/gbe.ts) records evidence in `player_minutes_monthly`, `club_season_outcomes`, `national_team_months` and the `player_gbe` cache (migration 3; optional in older saves). It recalculates weekly once the month or ruleset changes (all players), for every player at rollover, for squad players after each senior international window, and on request when stale (club changed, cache older than 38 days, ruleset changed). Older worlds and saves are backfilled on the next advance or save load. A senior *International Friendlies* competition puts every nation in the March and June FIFA windows, and nations outside their confederation's Nations Series also on its autumn dates (about ten matches a year). Friendlies count only for nations that played fewer than 30% competitive matches. The breakdown is on the player sheet, in the signing registration preview and at `GET /api/players/:id/gbe`. Development measurement (12 nations, about 22,500 senior club players): capped internationals averaged about 34 points with a 95% pass rate, uncapped players about 7 points with 16–18%. After a season, the six league bands averaged 21.1 / 16.2 / 12.0 / 7.7 / 5.1 / 2.4 points, with 63% / 55% / 38% / 2% / 0% / 0% of non-exempt players passing.
- **Calibration and longevity:** a deterministic 600-match sample is checked against pinned CC0 OpenFootball result aggregates from two completed seasons, plus explicit sanity bounds for other statistics. The optional season soak uses an isolated two-country world and checks intake, archived tables, closed accounts, SQL constraints and the storage footprint budget (it fails when `players` exceeds 10 KB per row or the other tables outgrow `seasonBudgetMB`). Earlier SQLite soak results do not establish that the SQL version passes. The full-world browser suite targets a shorter simulated period and fresh full-sized career generation. Neither is a decades-long full-world balance guarantee; a full season played on the Raspberry Pi has not been recorded yet.

The source links, calibration provenance and commands are in the [simulation architecture guide](website/src/content/docs/technical/simulation.md) and [DEVELOPMENT.md](DEVELOPMENT.md). Historical engine versions and already-scheduled old-save calendars are preserved.

## Known Gaps And Deliberate Platform Constraints

These remain requirements/fidelity gaps, not claimed as fully completed features:

- **Real-world competition regulations:** UEFA league-phase opponent/pot/association constraints and two-legged senior ties are implemented, but every official access-list qualifying path, coefficient bonus, knockout bracket protection and matchday venue-sequence rule is not. Pre-career coefficient history starts from association reputation, not licensed historical rankings. Non-UEFA knockout variants, Copinha's entire real entry field and all real national tournament calendars remain generalized. Continental youth events use U17/U19 even where real confederations use different age bands; FIFA U20 scheduling is not fully regulation-accurate.
- **International selection depth:** national squads are selected from eligible nationalities and ages, one squad per player (the oldest team first), with club release rules for youth tournaments. Dual-nationality switching, Olympic football, relationship costs of refusals, travel beyond a fitness penalty and all overlapping club/country eligibility rules are not modelled.
- **Match fidelity:** the engine is custom, stochastic and event-based. Aggregate result calibration is not equivalent to SofaScore or professional event/tracking-data calibration. VAR, detailed referee positioning, every penalty/offside law and association-specific disciplinary exceptions are not exhaustive. Expanded worlds start with full age-group rosters, but injuries, departures and older unexpanded saves can still leave too few available players; the engine enforces the seven-player minimum and records an abandoned match separately from event totals.
- **Regulatory realism:** source-based accounting and FA point tables are modeled, but not every association's laws, audit adjustments, permitted-loss exceptions or employment rules. Sanctions are a simplified set of UEFA, Premier League, solvency and administration rules decided automatically, without hearings, appeals or negotiated outcomes. FA ranking inputs use simulated national reputation order, not historical FIFA lists; pre-career playing evidence is a generated estimate labelled `estimate` in the breakdown, not real history, and evidence that is missing is reported as `no_data`, not zero. ESC/exception-panel pathways are not automated. Work authorisation is modelled only for English registration; other associations register players without a permit check. Real UK immigration rules would stop a signing without a work permit; Touchline deliberately lets the signing complete and leaves the player unregistered. Generated finances do not reconstruct pre-save historical balance sheets; revenue projections remain game heuristics and UEFA currency conversion is fixed at EUR 1 = GBP 0.86.
- **Individual awards:** competition pages show a live top-scorer race from the season totals, but the game awards no individual honours (player of the season, top scorer, team of the season), so player honours list team titles only.
- **World market calibration:** the volume bands in `simulation:check` (`MARKET_TARGETS`: tier 1 8–15 incoming senior moves per club per season, tier 2 6–12, tier 3 4–10, tier 4+ 2–10, lowest tier 2–6; loans 30–45%) are reported, not enforced. In the development three-season soaks the top flight averaged 6.6–8.7, at or below the bottom of its band (34–64% of top-flight clubs within it), and volumes were lowest in season 3 in both soaks: tier 1 went from 8.7 to 7.7 to 6.6 (England + Spain + Germany) and from 7.8 to 8.2 to 7.0 (England + Spain), the lowest tier to 3.1–3.5. The loan share fell from 40–41% in the first season to 25–29% while free signings rose from 2% to 12–13%. This season-3 tendency is not yet explained or corrected, and the market has not been calibrated beyond three seasons, over a full-world season or on the Pi.
- **Deadline week:** clubs stop making offers for the director's players seven days before deadline day so an accepted deal can still register, so the director receives no new offers in deadline week while AI clubs keep trading among themselves. The AI rush is modest: in the full-world development measurement, the last week of August saw 145–246 moves a day and deadline day 331, against roughly 130–150 a day in mid-August, and deadline day carried 3–6% of a season's moves in the soaks. There is no separate deadline-day model (late loan rushes, panic buys) beyond the day weighting and the over-budget mutual-consent releases.
- **Club life and ownership depth:** owners, multi-club groups, presidents and their promises are fictional and rule-based. There is no owners' and directors' test, detailed takeover financing or legal challenge; UEFA's multi-club rule is reduced to a blind trust before 1 March or exclusion; administration points and exits are simplified per association. Directors of football exist only at AI clubs (the human is the director at his own club). Injury history starts when a career is upgraded (earlier injuries are not reconstructed), and whole-career milestones are kept only for players who started their senior career in the game.
- **Loan realism depth:** the director cannot shop his own players to a chosen club; he marks them available and answers the offers clubs make. Promises influence selection priorities but do not force a manager to satisfy guaranteed minutes. A sell-on loan grants the development club a share of a later parent-club sale; other commercial interpretations would need separate clause types. Loan-club reputation, facilities and trust represent environment rather than a full off-field agent-based society.
- **World evolution balance:** managers move through appointment/dismissal histories, but there is no complete manager labour market or tactical-coaching tree. League reputation evolves heuristically. Full-world long-term economic and player-population balance has not been validated over many decades. Annual retirement/intake does not keep the initial population fixed.
- **Human behavior:** media, social posts, alliances, rivalries, fan protests, mental wellbeing and lifestyle consequences are bounded rule-based simulations. They are not human psychological models or generative-AI services. Detailed supporter subcultures, interview transcripts and every emergent political scenario are not exhaustive.
- **Visual platform:** Lucide replaces Apple-only SF Symbols on Linux/browser platforms. There are no player faces. Vibration is best-effort and unavailable in many desktop browsers. Glass blur/reduced motion depend on browser support.
- **Per-user hosting limits:** provisioned accounts have independent worlds and save catalogs, but share one runtime, database role, database and capacity budget. Isolation is enforced by authenticated account routing and schema scoping, not separate per-user SQL principals. Competitive multiplayer, read-only guest roles and automatic offline/hosted merging remain out of scope. Portable exports support explicit recovery/transfer, not account rebinding.
- **Weather:** temperature, wind and humidity are seeded from season and approximate climate, with match effects. No live forecast or full atmospheric simulation is included.
- **Scouting exposure:** scout estimates remain uncertain, but the requested all-player database and full dossiers expose underlying ability/potential. A separate fog-of-war difficulty mode is not implemented.
- **Performance:** simulation is server-side; each simulated day commits separately, but a multi-day request still occupies the API process and holds other actions of that world until it finishes while the browser shows progress. There is no worker-thread job queue or resumable mid-day cancellation yet. The Raspberry Pi 4's CPU makes full-world days and world generation markedly slower than on a desktop; this is unmeasured. Migration 2 rewrites each world's `players` table once without a statement timeout; its duration on the owner's Pi career is unmeasured. The living-world passes (world market, club life, ownership, player records) and migrations 6–9 have only development measurements on an x86 desktop (6.6 s per full-world day on average over the first 67 days from 1 July); their cost on the Pi is unmeasured. Snapshot storage and match history consume database capacity over time.

The implementation should be extended against these explicit gaps rather than described as an exact, fully realistic completion of the entire original blueprint.
