# Graphify benchmark: agentic changes to Touchline

Does the [Graphify](https://github.com/Graphify-Labs/graphify) code graph make a coding agent cheaper and more accurate on Touchline? Arm **A** answers with normal search (grep, file reads); arm **B** has the committed graph, the Graphify skill and Copilot instructions; arm **C** is B plus one prompt line asking the agent to start with the graphify CLI. Same question, model and tools otherwise. Generated by `npm run bench:graphify` ([index.ts](index.ts)); raw data in [results/](results/).

Commit `46e09b2`, 2026-11-10, graphify 0.9.105, copilot 1.0.108. CLI.

## Findings

**Verdict: on Touchline today, Graphify does not make agents cheaper or more accurate. Reaching for the graph actually costs a little more.** Across 72 real sessions, all three arms have the same accuracy (98–100%, no hallucinations in any arm). At arm level, B and C used 16–20% fewer tool calls, 11–14% less output and up to 6% fewer billed AI units. The tool-call and output savings do not come from the graph.

- **Runs that called graphify used 11% more input tokens than grep-only runs on the same task. Graph-arm runs that skipped graphify used 27% fewer.** On T2–T5, where every B and C run used the graph, mean input tokens rose 17%: 150k against 128k for A. T3 (blast radius) shows it most clearly: 82k with the graph, 51k with a single grep. The biggest arm-level wins, T6 in B (53k against 159k) and T8 in B (81k against 123k), came from runs that never called graphify; the agent wrote a single shell pipeline instead. That points to sampling noise, or the instructions shaping how the agent searches, rather than the graph itself.
- **Agents use the graph as well as grep, not instead of it.** In 21 of the 35 runs that called graphify, the same shell command also ran grep, typically `graphify query …; grep -rn …`. The graph's output is extra context. Agents double-check it because call edges are inferred and the graph can't see URL strings, so the extra cost is rational.
- **Where it hurt most:** T4 (migration change plan) cost 245k (B) and 207k (C) against 167k (A). B also missed `CONTRIBUTING.md` twice, because a graph of code symbols does not surface documentation that must change with the code. Nudged agents tried `graphify god-nodes` for T6, which the instructions warn ranks by edge count rather than imports, and had to fall back to grep.
- **Adoption needed explicit guidance, and the nudge didn't pay off.** With the original short instructions, B agents never called graphify (smoke run). With the command table now in [.github/copilot-instructions.md](../../.github/copilot-instructions.md), B used it in 58% of runs; one prompt line raised that to 88% (C). C matched A on accuracy and cost (+0% input tokens). No agent used graphify for T1 (most-imported modules); every agent preferred a grep and sort pipeline.
- **Scripted mode agrees.** Graphify's first answers are larger (+48% tokens in total), recall fewer of the answer-key items (61% against 88%), and are 30–70× slower per call (0.3–0.7 s against about 10 ms; negligible next to model latency). Only T3 `affected` (−75% tokens, full recall) and T2 `query` (−43%) beat a well-chosen grep, but in agent mode the agents still ran grep alongside them.
- **Scoring caveat:** T5 "misses" are not retrieval failures. Every T5 answer names `executeMarketTransfer` in its prose, but 5 of the 9 answers left it out of the JSON list, about evenly across arms (2/2/1).

**What would change the outcome:** Touchline is mid-sized (about 5.6k graph nodes) with consistent, greppable names, so grep is unusually effective here. Graphify's case is stronger where grep is weak: larger or older codebases, ambiguous names, or questions a single symbol search can't answer. To capture savings here, guidance would have to say "trust the graph and read only the files it names" rather than "graph before grep". That is a riskier instruction while edges are inferred. For now, keep the graph as an optional orientation and visualization aid; this benchmark gives no reason to push agents toward it.

## Method

- **Isolation.** Each arm is a git worktree of the same commit outside the repository with `scripts/bench-graphify` removed (no answer-key leaks). A also loses `graphify-out/`, `.github/skills/graphify` and `.github/copilot-instructions.md`, and a `PATH` shim makes `graphify` "command not found". B rebuilds its graph from the stripped tree. Every agent run gets an empty `COPILOT_HOME`, `--disable-builtin-mcps`, the same model and reasoning effort.
- **Prompts.** A and B get the same prompt, which never mentions Graphify: B agents only learn about it from the repository's skill and instructions, so B measures organic adoption. C adds exactly one line: "This repository has a Graphify code knowledge graph (graphify-out/graph.json). Start with the graphify CLI (graphify query, explain, path, affected) to locate the code, then verify with targeted reads."
- **Answer keys.** T1, T5 and T6 come from the TypeScript compiler API, T3 from the project's own `tsc` after really adding a required parameter, and T2, T4, T7 and T8 were traced by hand ([ground-truth.ts](ground-truth.ts), [tasks.ts](tasks.ts)).
- **Scoring.** The agent's final JSON block is matched by file and symbol; closed-set tasks score F1, open-ended ones recall. Items naming a missing file, or a symbol absent from the named file, count as hallucinated. No LLM judge.
- **Tokens.** Agent mode reports the CLI's own accounting (`session.usage_checkpoint`): input tokens include cached prompt tokens, which dominate every run (system prompt and tool schemas, about 24k per call). Scripted mode counts retrieved output with tiktoken o200k.

## Threats to validity

- Small sample (3 repeats per cell); model sampling noise is visible in the per-task spread, so read single-task differences cautiously.
- One codebase, one model. Graph usefulness depends on how well Graphify's TypeScript extraction resolves calls (it marks inferred edges; `.run()` style method calls are approximate).
- The control (T7) and limitation (T8) tasks are included on purpose: Graphify should not help with a one-grep lookup, and it cannot link a client URL string to an Express route.
- B agents may ignore the graph; the 'used graphify' figures show how often each arm actually called it. C shows the value when the graph is used, B what the repository integration achieves on its own.
- Scripted recipes are written with hindsight (the author knew the answers); they bound retrieval cost but say nothing about search strategy.
