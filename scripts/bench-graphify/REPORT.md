# Graphify benchmark v2: agentic changes to Touchline

Does the [Graphify](https://github.com/Graphify-Labs/graphify) code graph make a coding agent cheaper and more accurate on Touchline when it is used as designed? Four arms answer the same questions: **A** searches normally (grep, reads) with fair efficient-search instructions; **G** has the graph and a graph-first CLI protocol; **M** gets the graph through the Graphify MCP server; **H** is G plus a `preToolUse` hook that redirects the first search to the graph. Generated by `npm run bench:graphify` ([index.ts](index.ts)); raw data in [results/](results/); predictions in [hypotheses.md](hypotheses.md); v1 in [v1/REPORT.md](v1/REPORT.md).

Commit `009637b`, 2026-11-10, graphify 0.9.105, graph of 5653 nodes / 18046 edges built in 11 s.

## Method

- **Isolation.** Each arm is a git worktree of the same commit outside the repository with `scripts/bench-graphify` removed (no answer-key leaks). One graph is built (`graphify update .`, fixed hash seed) and copied to G, M and H. A has no `graphify-out/`, no Graphify skill and a `PATH` shim that makes `graphify` "command not found". Each arm's `.github/copilot-instructions.md` is replaced by its protocol in [arm-files/](arm-files/) (A gets equally detailed efficient-search tips, so the comparison is protocol against protocol). M has the CLI shimmed and the MCP server attached with `--additional-mcp-config`; H adds [arm-files/hooks](arm-files/hooks/). Every run gets an empty `COPILOT_HOME` and `--disable-builtin-mcps`.
- **Prompts.** Identical for every arm and never mention Graphify: arms differ only in what the repository provides.
- **Answer keys.** Computed with the TypeScript language service (call hierarchy, references) and the import graph in [ground-truth.ts](ground-truth.ts), frozen in [answer-keys.json](answer-keys.json); H6, T2, T8 and the H7 docs were traced by hand ([tasks.ts](tasks.ts)). Keys never come from Graphify.
- **Scoring.** The final JSON block is matched by file and symbol: closed sets score F1, open-ended tasks recall; failed runs score 0. No LLM judge.
- **Tokens.** From the CLI's `session.usage_checkpoint`. Retrieved tokens are o200k counts of every tool result the model received.

## Threats to validity

- 3 repeats per cell: CIs are wide on single tasks; group-level ratios are the headline.
- One codebase and Graphify's TypeScript call extraction: tests link to code mostly through imports (H4 is expected to favour grep), and string-built HTTP paths are invisible to the graph (T8).
- Structural tasks were chosen because they are graph-shaped; the claim is about that class of question, which v1 did not test. Controls (T7, v1 tasks) show the cost elsewhere.
- The A protocol is written to be fair, but any protocol can be improved; the arms compare realistic setups, not optimal ones.
